미리 보기문서 생성카드 등록프로젝트 추가근거 관리배포
01 · LOCAL PREVIEW

파일을 직접 열지 말고
HTTP로 확인합니다.

python -m http.server 8000

브라우저에서 http://localhost:8000을 엽니다. 상대 경로, history, asset 응답과 console 오류를 실제 배포에 가까운 조건에서 확인할 수 있습니다.

02 · CREATE DOCUMENT

공통 뼈대에서 시작합니다.

.\scripts\new-document.ps1 -Slug release-notes -Title "릴리스 노트"

templates/document.html을 바탕으로 docs/release-notes.html을 만듭니다. slug는 영문 소문자, 숫자, hyphen만 허용하며 기존 파일은 덮어쓰지 않습니다.

03 · REGISTER CARD

노출 정보는 data.js 한 곳에.

{
  title: "릴리스 노트",
  description: "변경점과 검증 결과",
  url: "docs/release-notes.html",
  project: "mobile-foundation",
  status: "진행중",
  version: "v0.2.0",
  updated: "2026-10-11",
  pinned: false,
  tags: ["Release", "Evidence"],
}

알맞은 section의 cards 배열에 추가합니다. 검색은 제목, 설명, 태그, 프로젝트, 섹션을 함께 읽습니다. 같은 URL을 두 번 등록하면 validator가 실패합니다.

04 · ADD PROJECT

새 프로젝트는 ID와 색을 먼저 정합니다.

{
  id: "next-project",
  label: "Next Project",
  color: "#e56f4a",
}

projects 배열에 추가한 뒤 카드의 project 값을 같은 ID로 지정합니다. 홈의 프로젝트 필터와 문서 수는 자동으로 만들어집니다.

05 · EVIDENCE RULE

숫자는 근거와 함께,
미확인은 그대로.

  • 성능, 빌드, 테스트 수치는 실행 날짜와 환경을 함께 적습니다.
  • 계획과 구현 완료를 같은 status로 표현하지 않습니다.
  • 기기나 live service가 없어 확인하지 못한 항목은 Unavailable 또는 Not configured로 둡니다.
  • credential, 개인 경로, SDK binary, APK는 문서 저장소에 넣지 않습니다.
06 · VALIDATE & DEPLOY

검증 후 main을 배포합니다.

powershell -ExecutionPolicy Bypass -File .\scripts\validate-site.ps1
git diff --check
git status --short

GitHub Pages source는 main 브랜치의 repository root입니다. .nojekyll을 유지하고, 모든 내부 link와 asset path는 상대 경로로 작성합니다.
