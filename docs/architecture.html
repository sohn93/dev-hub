SYSTEM DESIGN / ARCHITECTURE

Core는 계약을 알고,
게임은 SDK를 모릅니다.

의존성 방향과 명시적 연결을 통해 외부 SDK 변화가 앱의 중심 흐름으로 새지 않게 합니다.

01 · PACKAGE BOUNDARY

한 방향 의존성.

com.heosigames.mobile-template.core는 분석, crash reporting, 광고 계약에 vendor SDK 타입을 포함하지 않습니다. Firebase와 Ads 패키지는 각각 Core에만 의존하며 서로를 참조하지 않습니다.

프로젝트가 연결을 소유합니다

Editor builder가 AppRoot, scene, prefab의 참조를 생성 시점에 배선합니다. 런타임 hierarchy search나 Resources fallback은 사용하지 않습니다.

02 · STARTUP

초기화는 순서가 보이는 목록입니다.

  1. AppBootstrap이 serialized service 목록을 앞에서부터 실행합니다.
  2. 각 결과를 ServiceInitializationResult로 기록합니다.
  3. 선택적 서비스 실패는 진단에 남기고 다음 초기화를 계속합니다.
  4. 완료 후 initial screen으로 이동합니다.

장기 생존 객체인 AppRoot에는 bootstrap, lifecycle relay, navigation, localization, audio, Firebase, consent, ads component가 명시적으로 연결됩니다.

03 · UGUI FLOW

화면 전환과 Back 동작을
하나의 규칙으로.

  • UIViewRegistry가 고유한 UIViewId와 screen/popup 인스턴스를 연결합니다.
  • ScreenNavigator는 한 화면만 활성화하고 history를 기록합니다.
  • PopupStack은 LIFO 순서로 popup을 엽니다.
  • Android Back은 최상위 popup → 화면 history → root exit confirm 순서로 처리됩니다.
  • SafeAreaFitter는 지정된 RectTransform만 갱신합니다.
04 · LOCAL STATE

작고 명확한 기기 설정.

CsvLocalizationService는 inspector에 연결한 CSV TextAsset을 읽습니다. LocalizedText도 localization service와 TMP target을 직접 참조합니다.

언어와 BGM/SFX 설정은 Heosi.MobileTemplate.* PlayerPrefs key를 사용합니다. AudioService는 clip을 호출자로부터 받고 게임별 sound enum이나 asset loading 정책을 가지지 않습니다.

05 · SDK FLOW

동의와 준비 상태가
광고 요청보다 먼저 옵니다.

  1. Firebase dependency를 한 번 확인하고 App, Analytics, Crashlytics 준비 상태를 분리합니다.
  2. UMP consent 정보를 매 실행마다 갱신합니다.
  3. 동의 결과가 광고 요청을 허용할 때만 Mobile Ads를 초기화합니다.
  4. fullscreen과 privacy callback은 public request마다 최대 한 번만 완료됩니다.

Bootstrap timeout은 대기하는 호출자만 끝냅니다. UMP 처리는 계속되고, 늦게 성공하면 ConsentChanged를 통해 광고 초기화가 회복될 수 있습니다.

06 · EXTENSION

새 기능이 들어갈 자리.

새 startup integration은 IAppBootstrapService로 구현하고 목록에 명시적으로 등록합니다. 게임별 scene, content, reward, economy, save, backend policy는 패키지 밖에 둡니다.
