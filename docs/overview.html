포함제외시작기본값소유 경계
01 · INCLUDED

앱이 켜지고, 화면이 흐르고,
공통 서비스가 준비되는 데 필요한 것.

  • uGUI와 TextMesh Pro 기반 sample flow
  • serialized screen registry, 화면 history, popup stack
  • Android Back 우선순위와 safe-area 적용
  • CSV localization과 BGM/SFX 선호 설정
  • Firebase App, Analytics, Crashlytics adapter
  • Google Mobile Ads 전 광고 형식과 UMP 동의 adapter
  • Android 구성 validator, sample scene builder, development APK entry point
02 · EXCLUDED

게임마다 다시 결정해야 하는 것은
의도적으로 비웠습니다.

제외 영역이유
게임플레이와 콘텐츠장르와 프로젝트마다 달라지는 핵심 규칙
Save · economy · reward policy서버와 밸런스 정책에 종속
PlayFab · Firebase Auth · Google Sign-In모든 게임이 계정 시스템을 필요로 하지 않음
IAP · OneStore · Facebook SDK스토어와 사업 요구가 확정된 뒤 선택
DOTween공통 기반의 필수 의존성이 아님
03 · START A GAME

새 게임을 시작하는 순서.

  1. 스타터 저장소를 새 private 프로젝트로 복사합니다.
  2. product name과 Android application ID를 고유하게 바꿉니다.
  3. 새 package ID로 Firebase와 AdMob 앱을 등록합니다.
  4. Unity 6000.3.8f1에서 열고 Development validation을 실행합니다.
  5. 필요하면 sample scene builder로 committed sample assets를 재생성합니다.
  6. 게임 전용 코드는 패키지와 Assets/_Template 밖에 둡니다.
04 · DEFAULTS

복사 직후의 안전한 기본값.

TestGoogle sample ad IDs
Noneproduction credentials
DebugAndroid signing

저장소에는 google-services.json, keystore, production ad-unit ID가 없습니다. 광고 설정은 Google sample ID와 test mode를 사용합니다.

05 · OWNERSHIP

패키지가 아닌 프로젝트가 소유하는 것.

씬, 프리팹, sample UI, localization data, 앱별 설정, 외부 SDK binary, Android resolver output, Player Settings는 스타터 프로젝트가 소유합니다. embedded package를 복사하면 새 게임마다 독립적인 사본이 생깁니다.

확장 원칙

게임 코드는 SDK 구현이 아니라 Core runtime 계약에 의존합니다. rewarded ad 결과를 실제 보상으로 바꾸는 정책도 게임 코드에 둡니다.
